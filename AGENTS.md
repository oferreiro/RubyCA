# AGENTS.md

Sinatra-based certificate authority web app (no Rails): modular `Sinatra::Base`, Sequel + SQLite, Haml views, Puma server. Fork of phillcampbell/RubyCA for internal use.

## Setup (fresh clone — several required files are gitignored)

- `bundle install` — gems vendored to `vendor/bundle` (`.bundle/config` sets `BUNDLE_PATH`).
- `cp sample.env .env` — sets `APP_ENV`; the DB file is keyed on it: `db/rubyca-#{APP_ENV}.db`.
- `cp config/rubyca.yml.sample config/rubyca.yml` — app aborts at boot without it; loaded into global `$config`.
- `bundle exec rake db:migrate`.
- Ruby 4.0.3 expected. `.ruby-version` is gitignored; `utils/set_ruby_version` points PATH at Homebrew `ruby@4`.

## Commands

- Run app: `./RubyCA` (admin UI at `http://host:port/admin`).
- First run must generate the CA as root (`sudo ./RubyCA` / `sudo bundle exec rake ca:setup`) or explicitly unsafe (`./RubyCA --unsafe` / `bundle exec rake "ca:setup[unsafe]"`). Writes encrypted `private/root_ca.pem` (mode 0400); key passwords are prompted on stdin and never stored.
- Configured web port < 1024 requires root on every start (see `./RubyCA` check).
- CA maintenance: `rake ca:renew_root_certificate`, `rake ca:renew_intermediate_certificate` (prompt for key passwords on stdin).
- Admin accounts: `rake rodauth:create_admin` (prompts for email + password on a TTY, like the CA key prompts) and `rake rodauth:generate_hmac_secret` (writes `web.admin.hmac_secret` into `config/rubyca.yml`; refuses to overwrite an existing secret). TOTP rescue tasks (prompt for email on stdin): `rake rodauth:reset_totp_lockout` (zeroes the failure counter and repairs `last_use`, keeping TOTP) and `rake rodauth:disable_totp` (drops TOTP + recovery codes, restoring password-only login). `rake rodauth:manage_accounts` is an interactive menu covering all of the above plus list, change password, change email and delete (deletion asks you to retype the email and warns when it's the last account). All of these share `tasks/rodauth_accounts.rb` (`RodauthAccounts` module; failures raise `RodauthAccounts::Error`, which the single-purpose tasks turn into `abort` and the menu prints before showing the menu again).
- Migrations: `rake db:generate_migration[name]`, `db:migrate`, `db:rollback[target]`, `db:reset`. Note `rake db:version` always prints 0 — it reads `schema_info`, but timestamped migrations use `schema_migrations`. Also `db:rollback`/`db:reset` are currently broken (`NameError: uninitialized constant DB` — they never open a connection); edit the DB manually or re-migrate instead.
- Version: `rake version:current` / `rake version:bump[major|minor|patch]` — writes the `version` file (read into `RUBYCA_VERSION` at boot).
- Puma daemon deploy: `cp distrib/puma/puma-sample.rb config/puma.rb`, `rake deploy:puma_directories` (creates `tmp/sockets`, `tmp/pids`, etc.), `bundle exec puma -C config/puma.rb`. systemd units in `distrib/*/init/`.
- Legacy 2.x DataMapper import: `rake db:migrate_dm_to_sequel` then `rake db:migrate_dm_crls_to_sequel` (source is the root-level `RubyCA.db`).

## Tests

- Minitest; there is no `rake test` task. Run each file directly: `bundle exec ruby test/models/certificate_test.rb`.
- Auth integration tests: `bundle exec ruby test/auth/rodauth_test.rb` (Minitest + Rack::Test; covers the IP-allowlist bypass (except `/admin/config[s]`, which must require login + TOTP even from allowlisted IPs), login redirect, deep-link return-to after login and 2FA, password login, nav state (Login vs Two-Factor/Logout links), TOTP enrollment + 2FA round-trip (immediate login after enrollment and a second round after a success), the TOTP lockout explanation page, recovery codes, the negative paths (wrong password, wrong TOTP code counting `num_failures`, invalid recovery code not consumed), CSRF-less POSTs, and the disable flows (`otp-disable` and `multifactor-disable` restore password-only login); seeds its own admin in `DB`). Tests are hermetic about the allowlist: `setup` replaces `$config['web']['admin']['allowed_ips']` with `127.0.0.1` and `teardown` restores it. Note `account_otp_keys.last_use` must hold *local* timestamps: SQLite's `CURRENT_TIMESTAMP` (the column default) is UTC while Sequel reads the column as local time, so a future `last_use` makes rotp's replay filter reject every code with "Invalid authentication code" — the cause of the original TOTP lockout. `core/web/auth.rb` normalizes both write paths (`after_otp_setup` backdates at enrollment, `otp_update_last_use` writes `Time.now`); the tests cover it without manual backdating.
- Access-control unit tests: `bundle exec ruby test/auth/access_control_test.rb` — pure tests for `RubyCA::Core::Web::AccessControl.host_allowed?` (CIDR ranges, IPv4/IPv6 mismatches, malformed input, nil/empty allowlists) and `admin_authentication_required?` (Settings paths forced to authenticate even from allowlisted IPs, other admin paths still bypassing, nil-path fallback); no Rack or DB involved. Requires `core/web/auth` explicitly (test_helper doesn't load it).
- Rake task tests: `bundle exec ruby test/auth/rodauth_rake_test.rb` — in-process tests for the `rodauth:*` tasks, including `manage_accounts` menu sessions scripted as stdin lines. `Rake.application.init` + `load_rakefile` loads all tasks; a `FakeStdin` double replaces `STDIN` (tasks call `STDIN.gets` / `STDIN.noecho(&:gets)`), output is captured via `$stdout`/`$stderr` reassignment, and `abort` surfaces as a rescued `SystemExit` (status 1). The `generate_hmac_secret` happy path writes the real `config/rubyca.yml`, so only its no-overwrite guard is tested. Loading the rake file re-requires `core/bootstrap`, which rebinds `DB` to a second connection on the same file — harmless, but each connection is a separate transaction scope.
- Prerequisite (once): `APP_ENV=test bundle exec rake db:migrate`. Reason: `test_helper.rb` migrates an in-memory DB and sets `Sequel::Model.db` to it (models use it), but requiring `core/bootstrap` rebinds the `DB` constant to the file `db/rubyca-test.db`, so raw `DB[:table]` calls in tests hit the file DB — without the migration they fail with `no such table`.
- Tests abort without a `config/rubyca.yml` (required by `core/load`); the auth tests overwrite the real config's `allowed_ips` for the duration of each test (restored in `teardown`), but still read the real `hmac_secret` and `domain` — a config where `127.0.0.1` is reachable is assumed.
- Suite state (test/ was uncommitted WIP as of Oct 2026): `test/models/certificate_test.rb`, `test/ca/ca_setup_test.rb`, `test/ca/fill_console_test.rb`, `test/auth/rodauth_test.rb`, `test/auth/access_control_test.rb`, `test/auth/rodauth_rake_test.rb` pass; `test/ca/setup_test.rb` fails, `test/ca/my_fill_console_test.rb` errors. Don't treat those as regressions without checking.

## Architecture / wiring

- Entrypoints are `./RubyCA` and `config.ru`. Both set `$root_dir` then require `core/load` → `core/bootstrap` (→ `core/ca/setup` for the CLI). Files in `core/` abort if executed directly (`if __FILE__ == $0`) and depend on this load order — don't require models or `core/ca/setup` before `core/load`/`core/bootstrap` (they rely on globals `$config`, `$root_dir`, `$default_cipher`, `DB`).
- `core/load.rb`: Bundler.require, dotenv, loads config into `$config`, sets `$default_cipher` (default `AES-256-CBC`).
- `core/bootstrap.rb`: opens `DB` (SQLite, log at `log/db-#{APP_ENV}.log`) and requires models in `core/models/` (thin `Sequel::Model` classes; `certificates` ↔ `crls` is one-to-one, `cn` unique).
- `core/ca/setup.rb`: CA generation/renewal as top-level methods (`first_run_setup`, `gen_self_signed_root`, `create_crl`, `renew_*`); the `ca:*` rake tasks require this file directly.
- Web: all routes live in the single class in `core/web/server.rb`, mostly under `/admin/...`; Haml views in `core/web/views/`, vendored Bootstrap/Popper in `core/web/public/`. `/admin` is gated by `web.admin.allowed_ips` in config (allowed IPs bypass login entirely), except `/admin/config` and `/admin/configs` (the Settings page that edits the allowlist and 2FA), which always require login.
- Admin auth: Rodauth (2.x) as Rack middleware — `RodauthApp` in `core/web/auth.rb`, required after `core/bootstrap` and before `core/web/server` in both entrypoints, then `use`d by Sinatra after `Rack::Session::Pool`. Login + optional TOTP 2FA + recovery codes under `/auth/*`, Haml views in `core/web/views/auth/` overriding Rodauth's built-in templates. Login and second-factor redirects preserve the originally requested same-origin GET path (`login_return_to_requested_location?` / `two_factor_auth_return_to_requested_location?`), so a deep link such as Settings > "View Auth Recovery Codes" survives the login + TOTP steps and lands on the password-confirmation form. `AccessControl.admin_authentication_required?` forces login (and TOTP, when enrolled) for `/admin/config` and `/admin/configs` even from allowlisted IPs, since Settings edits the allowlist itself; the middleware route block and the Sinatra fallback share it. The `/admin` gate lives in the middleware route block (so Rodauth's flash/session rotation work on the login redirect); Sinatra's `before '/admin*'` keeps an identical check as a fallback. `host_allowed?` is shared via `RubyCA::Core::Web::AccessControl` (auth.rb); the old config basic auth (SHA256 hashes, `protected!`/`authorized?`) is gone. Rodauth binds explicitly to the `DB` constant, so the test-rebinding gotcha applies to it too. A `route_csrf` failure block on the middleware app renders a plain 400 page for missing/invalid CSRF tokens instead of Roda's default (raising `RouteCsrf::InvalidToken`, which surfaces as a 500). Rodauth's `otp` feature needs `rotp` AND `rqrcode` at runtime. `account_otp_keys.last_use` is written as local `Time.now` (`after_otp_setup` and `otp_update_last_use` overrides in auth.rb): the column default `CURRENT_TIMESTAMP` is UTC on SQLite and reads back the UTC offset into the future, which makes rotp's replay filter reject every TOTP code.
- Client IP for the allowlist comes only from `AccessControl.client_ip(env)`: `X-Real-IP` / last `X-Forwarded-For` hop are honoured only when `REMOTE_ADDR` is in `web.trusted_proxies` (default loopback). Don't read those headers or `request.ip` directly — Rack trusts all private ranges as proxies, so a LAN client could claim 127.0.0.1. `admin_path_requires_authentication?` decodes the path first because Sinatra/Mustermann routes `/admin/%63onfig` to `/admin/config`; Sinatra also has a `before '/admin/config*'` filter that forces login.
- CSRF on Sinatra admin forms: every non-GET `/admin*` request needs `authenticity_token` (per-session, rendered by the `csrf_tag` helper — add `!= csrf_tag` to any new POST form) or it gets a 403 (`invalid_csrf.haml`). Script endpoints go in `Server::CSRF_EXEMPT_PATHS` (currently `/admin/crl/renew.txt`, used by `distrib/rubyca-check-crl`). Rodauth's `/auth/*` forms use their own `route_csrf` `_csrf` tokens.
- Set `web.admin.hmac_secret` before anyone enrolls TOTP: Rodauth HMACs the TOTP secret once a secret exists, so adding one later invalidates enrolled authenticators. `rake rodauth:generate_hmac_secret` refuses while OTP keys exist, and the app warns at boot when the secret is blank.
- Flash messages are rendered unescaped (`styled_flash`); wrap user-derived values with the `h` helper.
- `core/privileges.rb` monkey-patches EventMachine to drop privileges after binding a port (Thin legacy); Puma is the default server now.
- `core/aux.rb#legacy_pkcs12` shells out to the `openssl` CLI via `spawn` — the openssl binary is a runtime dependency for legacy PKCS#12 export.

## Gotchas

- `.gitignore` hides operational files: `config/rubyca.yml`, `.env*`, `private/`, `*.db`, `.ruby-version`, `Gemfile.lock`, `vendor/`, `bak/`. Never commit keys/DBs/env files; presence on disk does not mean they're tracked.
- `Gemfile.lock` is gitignored, so dependency resolution floats within Gemfile constraints — don't assume the local lockfile reflects the repo.
